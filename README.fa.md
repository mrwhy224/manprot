# نمونهٔ نمایشی «رُبات‌یار»

نمونهٔ اولیهٔ راست‌به‌چپ برای مدیریت پروژه‌های رباتیک، ثبت زمان، هزینه و پیش‌نمایش یکپارچه‌سازی‌ها. تمام داده‌ها ساختگی‌اند و واحد مبلغ‌ها **تومان** و واحد زمان **نفر-ساعت** است.

## اجرا

این محیط در زمان ساخت PHP، Composer، Laravel و دسترسی DNS به npm نداشت؛ در نتیجه starter kit رسمی Laravel + React/Inertia قابل نصب نبود. برای آن‌که نمونه بدون وابستگی و واقعاً قابل اجرا بماند، نسخهٔ حاضر یک برنامهٔ ES-module استاتیک است.

```bash
cd /home/mahdi/manprot
npm run serve
# سپس http://localhost:5173 را باز کنید
```

برای بررسی منطق محاسبات:

```bash
npm test
```

## مسیرهای نمایشی

مسیرهای هش مرورگر عبارت‌اند از `#mine`، `#board`، `#project`، `#portfolio`، `#integrations` و `#knowledge`. ناوبری بر اساس نقش نمایشی محدود می‌شود.

نقش‌های قابل انتخاب (بدون گذرواژه) عبارت‌اند از عضو تیم، رهبر فنی، مدیر پروژه، مالی و مدیر ارشد. این نقش‌گردان فقط ابزار ارائه است؛ در نسخهٔ تولیدی کنترل دسترسی باید در Laravel و سمت سرور هم enforce شود.

## چه چیزهایی پیاده‌سازی شده است

- زنجیرهٔ یکپارچهٔ مشتری ← قرارداد ← پروژه ← بستهٔ کاری ← وظیفه ← ثبت زمان ← هزینهٔ کار ← داشبورد پروژه.
- دادهٔ مرکزی و type-like domain model در `src/core.mjs`؛ شامل ۴ پروژهٔ مشتری با وضعیت سالم/ریسک/بیش‌بودجه/تکمیل‌شده و یک پروژهٔ R&D داخلی.
- ذخیرهٔ تعاملی در `localStorage` با دکمهٔ «بازنشانی داده‌های نمایشی».
- ثبت سریع زمان از خانه یا داخل وظیفه، با به‌روزرسانی ساعت روز، ساعت بستهٔ کاری، هزینهٔ کار و پیش‌بینی پروژه از یک منبع داده.
- برد وظایف با وضعیت‌های آماده انجام، در حال انجام، آماده بررسی و انجام‌شده؛ یادداشت، مسدودی و ثبت زمان. «آماده بررسی»، پذیرش تحویل‌دادنی و تایید زمان عمداً از هم تفکیک شده‌اند.
- نمای پروژه با قرارداد، صورتحساب و وصول جداگانه؛ milestone، ریسک، تغییرات، و drill-down ثبت‌های زمان.
- پرتفوی و محاسبهٔ هزینهٔ واقعی، هزینهٔ باقی‌مانده، هزینهٔ نهایی، درآمد/سود/حاشیهٔ پیش‌بینی؛ نرخ نیروی کار از نرخ ثبت تاریخی استفاده می‌کند.
- پیش‌نمایش حضور و غیاب و «شبیه‌سازی اتصال سپیدار» با صف مغایرت. اقلام شبیه‌سازی حسابداری دوباره در هزینهٔ پروژه جمع نمی‌شوند.
- دستیار دانش پروژه با پاسخ‌های سناریویی منبع‌دار، شامل نمونهٔ منع دسترسی به مالی برای نقش‌های غیرمالی.

## لایهٔ داده و محدودیت‌ها

`src/domain.d.ts` قرارداد TypeScript دامنه و `DemoRepository` در `src/repository.mjs` adapter کوچک browser storage را مشخص می‌کنند. در تولید، پیاده‌سازی هم‌نام می‌تواند به Laravel API و SQLite/PostgreSQL متصل شود، بدون آن‌که هر صفحه بازنویسی شود. این نمونه **دیتابیس ندارد**؛ هیچ SQLite صرفاً برای ورود یا session اضافه نشده است.

پاسخ‌های دستیار دانش، اتصال سپیدار و حضور، داده‌های مالی و نقش‌ها همگی شبیه‌سازی‌اند: هیچ API زنده، اعتبارنامه، اثرانگشت، همگام‌سازی چندکاربره، LLM یا embedding وجود ندارد و این ارقام حقیقت حسابداری نیستند.

## مسیر پیشنهادی برای تولید

1. پس از فراهم شدن PHP/Composer و شبکه، با starter kit رسمی Laravel React/Inertia + TypeScript scaffold کنید و همین مدل‌های دامنه را به `resources/js` منتقل کنید.
2. یک API/Repository سمت سرور با مجوزهای policy، audit log و migrationهای پروژه، بسته‌کاری، وظیفه، ثبت‌زمان، هزینه و نرخ تاریخی اضافه کنید.
3. یکپارچه‌سازی حضور و سپیدار را با صف مغایرت، idempotency و تأیید انسانی پیاده کنید؛ خرید قطعه را از مصرف پروژه جدا نگه دارید.
4. دستیار دانش را پس از تعیین ACL سند، retrieval قابل‌ردیابی، ارجاع و ارزیابی پاسخ به RAG واقعی متصل کنید.
